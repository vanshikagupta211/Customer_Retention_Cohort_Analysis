# 📊 Customer Retention & Cohort Analysis

*An end-to-end data analytics project using SQL Server, Python, and Power BI*

*Author:* Vanshika Gupta

---

## 📌 Project Overview

Customer retention is a critical business metric because retaining existing customers can significantly contribute to long-term revenue and business growth.

This end-to-end data analytics project analyzes transaction-level retail data to understand customer purchasing behavior, retention patterns, cohort performance, revenue contribution, product performance, purchase frequency, and geographic sales trends.

The project combines **SQL Server, Python, and Power BI** to demonstrate a complete analytics workflow:

**Data Profiling → Data Cleaning → Exploratory Analysis → Cohort Analysis → Business Analysis → Interactive Dashboards → Business Insights**

---

## 🎯 Business Objective

The primary objective of this project is to understand customer retention and purchasing behavior and identify the factors that contribute to revenue.

The analysis addresses key business questions such as:

- How many customers are repeat customers?
- What percentage of customers return after their first purchase?
- How does customer retention change over time?
- Which customer cohorts demonstrate stronger retention?
- How much revenue is generated by repeat customers?
- Which customers generate the highest revenue?
- Which products generate the highest revenue and unit sales?
- How frequently do customers place orders?
- Which countries contribute the most revenue and customers?
- How do revenue and Average Order Value change over time?
- Which customer segments should receive greater retention focus?

## 🧹 Data Cleaning & Preparation
The raw dataset was independently analyzed and cleaned using SQL Server and Python.

### Data Quality Checks
The following issues were investigated:
- Missing Customer IDs
- Missing product descriptions
- Duplicate transactions
- Negative quantities and Cancellation-related transactions
- Zero or negative unit prices
- Invalid invoice records
- Transaction-level revenue calculation
- Date consistency
- Customer-level transaction history

### Revenue Calculation

A transaction-level revenue field was created:

*Revenue = Quantity × UnitPrice*

Additional analytical fields were created for customer and cohort analysis:

* PurchaseMonth
* CohortMonth
* CohortIndex
* CustomerType

### Python Cleaning Results

| Metric                   |  Result |
| ------------------------ | ------: |
| Raw transaction rows     | 541,909 |
| Cleaned transaction rows | 392,692 |
| Unique customers         |   4,338 |
| Remaining duplicate rows |       0 |

The Python cleaning workflow removed records with missing customer IDs, removed exact duplicates, excluded nonpositive quantities and unit prices, converted customer IDs to integers, and calculated revenue.

*Note:* SQL and Python were used as independent cleaning workflows. Their final row counts differ because of differences in cleaning and exclusion logic. The results should not be treated as identical datasets.

## 📅 Cohort Analysis

Cohort analysis groups customers according to their first purchase month and tracks their subsequent purchasing activity.

### Cohort Definition

*Cohort Month:* The month of a customer's first purchase.

*Cohort Index:* The number of months since the customer's first purchase, with Month 1 representing the initial purchase month in Python and Power BI.

### Retention Calculation

$$
\text{Retention Rate} =
\frac{\text{Customers Active in Month N}}
{\text{Original Cohort Size}}
\times 100
$$

The analysis produces a cohort retention matrix and heatmap to compare customer retention across acquisition cohorts.

### Cohort Retention Results

| Metric                    | Result |
| ------------------------- | -----: |
| Monthly cohorts           |     13 |
| Average Month-1 Retention |  20.6% |
| Average Month-3 Retention |  23.2% |

These metrics summarize the Power BI cohort analysis. Retention comparisons should account for the fact that newer cohorts have fewer observed months.

*Month numbering note:* SQL uses Month 0 for the initial purchase month, whereas Python and Power BI use Cohort Index 1. These represent the same initial cohort period.

## 📈 Customer Purchase Frequency

Customer purchase frequency was calculated using the number of distinct invoices associated with each customer.

Key observations:

* Many customers place relatively few orders.
* A smaller group of customers places substantially more orders.
* Purchase frequency follows a long-tail pattern.
* The highest observed frequency was 209 distinct orders for one customer.

This analysis helps distinguish occasional buyers from highly engaged repeat customers.

## 🧮 Key DAX Measures

The following are examples of measures used in the Power BI report.

*Total Revenue*

dax
Total Revenue =
SUM(customer_retention_powerbi[Revenue])


*Total Orders*

dax
Total Orders =
DISTINCTCOUNT(customer_retention_powerbi[InvoiceNo])


*Total Customers*

dax
Total Customers =
DISTINCTCOUNT(customer_retention_powerbi[CustomerID])


*Repeat Customers*

dax
Repeat Customers =
CALCULATE(
    DISTINCTCOUNT(customer_retention_powerbi[CustomerID]),
    customer_retention_powerbi[CustomerType] = "Repeat Customer"
)


*Repeat Customer Rate*

dax
Repeat Customer Rate =
DIVIDE(
    [Repeat Customers],
    [Total Customers],
    0
)


*Average Order Value*

dax
Average Order Value =
DIVIDE(
    [Total Revenue],
    [Total Orders],
    0
)

A dedicated table that organizes the report's DAX measures. It is not connected to the transaction tables through relationships.
